# Claude Design に投げるプロンプト（Meowbox UI v0.1）

---- ここから下をそのままコピペ ----

Meowbox（ミャオボックス）というデスクトップメールアプリの UI をデザインしてください。
Tauri v2 + React で実装するので、Web 技術で再現可能なデザインにしてください。

## プロダクト概要
- フリーランスエンジニアが、案件ごとに配布される複数のメールアドレス（会社ドメイン、Gmail、Microsoft 365 など）を 1 つのアプリで一元管理するためのメーラー
- 最大の特徴は AI（Claude）との連携。AI がスレッド要約・タスク抽出・返信下書きを作り、人間は「確認して送信」だけを行う
- AI は送信できない。送信は必ず人間が UI の承認ボタンを押す。この「人間が最後の判断をする」安心感をデザインで表現したい
- 主なユーザーは自分 1 人。日本語 UI。1 日に数十通、5〜10 スレッドを捌く想定

## トーン & スタイル
- 名前の由来は Mailbox × 猫の鳴き声。**猫モチーフはアクセント程度**（ロゴ、空状態のイラスト、ローディング、成功トースト）に留め、メイン画面は仕事で毎日使える落ち着いた業務ツールの質感にする。可愛すぎて集中を削ぐデザインは避ける
- 参考にしたい質感: Linear、Arc、Superhuman、Raycast。密度は高め、余白は締める、フォントは小さめでも読みやすく
- ライト / ダーク両対応。デフォルトはダーク
- アクセントカラーは 1 色（温かみのあるオレンジ〜アンバー系、猫の目や毛色を連想させる色）。AI 由来の要素（要約、AI 抽出タスク、AI 下書き）にはアクセントとは別の「AI カラー」（薄い紫やティール）を一貫して使い、**人間が書いたものと AI が書いたものが一目で区別できる**ようにする
- 日本語フォントを前提にした行間・字間。英数字は等幅寄りでも可
- アイコンは線画（Lucide 系）

## 情報構造（3 ペイン + 右パネル）
1. **左サイドバー（幅 220px 前後、折りたたみ可）**
   - 上: アプリロゴ（猫 + 封筒）、検索ボックス（⌘K でコマンドパレット）
   - 「案件」セクション: 案件タグごとにグループ化されたアカウント一覧。例:
     - 自社（me@my-company.example）
     - 案件A（a-project@client-a.co.jp, a-project@gmail.com）
     - 案件B（b@client-b.onmicrosoft.com）
     - 各案件に未読数バッジ、同期状態のドット（緑=同期済 / 黄=同期中 / 赤=エラー）
   - 「ビュー」セクション: すべて / 未読 / 要対応（AI がアクション必要と判定） / フラグ / タスク / 下書き
   - 下: 同期ステータス、設定ギア
2. **中央: スレッド一覧（幅 360〜420px）**
   - 上部にビュー名 + フィルタチップ（案件 / 未読 / 要対応 / 期間）
   - 1 行 = 1 スレッド。差出人名、件名、AI 要約の 1 行目（AI カラーで薄く）、日時、案件タグ、未読ドット、添付アイコン、AI 抽出タスク数バッジ
   - 「要対応」スレッドには左端に細いアクセントバー
   - キーボード操作前提（j/k 移動、e アーカイブ、r 返信）。ホバーで右端にクイックアクション
3. **右: スレッド表示（残り幅）**
   - 上部に **AI 要約カード**（AI カラーの薄い背景、「Claude による要約」ラベル、生成日時、再生成ボタン）。3〜5 行で「何の話か / 相手が求めていること / 期限」
   - その下に **抽出タスクのリスト**（チェックボックス、期日、confidence が低いものは点線枠で「候補」表示、「確定」「却下」ボタン）
   - メッセージは時系列で積む。引用部分は折りたたみ。添付はチップ表示
   - 最下部に返信エリア。「AI で下書き」ボタン → 下書きが AI カラーの枠で挿入され、編集可能。**送信ボタンは常に人間側の色（アクセント）で「確認して送信」というラベル**。AI 下書きを一切編集していない場合は送信前に軽い確認を出す
4. **右端パネル（トグル、幅 300px）**
   - 「今日のダイジェスト」: 案件横断で AI がまとめた未処理事項と期限。朝一で見る画面
   - タスク一覧（案件ごと、期日順）

## 作ってほしい画面
1. メイン画面（ダーク）— 3 ペイン + 右パネル開いた状態。自社 案件の「見積の件」スレッドを表示中、AI 要約とタスク 2 件（1 件は候補）が見えている状態
2. メイン画面（ライト）— 同じ内容
3. 返信下書き中の状態 — AI 下書きが挿入され、ユーザーが 1 行編集した直後。「確認して送信」ボタンが目立つ
4. 今日のダイジェスト（右パネル拡大 or モーダル）— 3 案件分の要対応事項と期限が並ぶ
5. アカウント追加ウィザード — 種別選択（IMAP / Gmail / Microsoft 365）→ 認証 → 案件タグ割り当て、の 3 ステップ
6. 空状態 — アカウント未登録の初回起動画面。ここは猫のイラストを使ってよい
7. コマンドパレット（⌘K）— 検索、案件切替、「このスレッドを要約」などの AI アクションが混在

## サンプルデータ（リアルにするため）
- 案件: 自社（社内システムの保守）、案件A（EC サイトのリニューアル）、案件B（複数 CMS サイトの運用）
- スレッド例:
  - 「Re: 見積の件」山田（client-a.co.jp）— 「追加要件 3 点の見積を今週金曜までに」。タスク: 「見積書を送る（9/5）」確定、「追加要件のヒアリング日程調整」候補
  - 「【至急】本番環境でエラー」佐藤（my-company.example）— 要対応、赤アクセント
  - 「9月定例のご案内」総務部 情報システム課 — タスク: 「9/12 14:00 定例参加」
  - 「Weekly digest」GitLab — 通知系、薄く表示
- 日本語の件名・本文で、ビジネスメールらしい文体

## 出力してほしいもの
- 上記 7 画面のアートボード（デスクトップ 1440×900）
- カラートークン（ライト / ダーク、アクセント、AI カラー、セマンティック色）、タイポグラフィスケール、スペーシング、角丸、影の定義
- スレッド一覧の 1 行、AI 要約カード、タスク行、送信ボタンの 4 つはコンポーネント単体でも書き出す（状態バリエーション込み）
- Tailwind で再現しやすいよう、色は HSL か HEX で明示

## やらないでほしいこと
- 猫要素を全面に出す（メイン画面に猫の顔を常駐させる等）
- AI 要素をキラキラさせすぎる（グラデーション多用、スパークルアイコン乱用）
- Gmail や Outlook の模倣。独自の密度感を持たせる

## 使い方メモ
- 上のプロンプトを Claude Design に貼る。最初は画面 1（ダーク）だけ作らせて方向性を固めてから残りを出させると手戻りが少ない
- 出てきたトークンは `apps/desktop/src/styles/tokens.css` に落とし、Tailwind の theme に流し込む想定
- 気に入った案は `docs/design/` に PNG で保存しておくと Claude Code に「この画面を実装して」と渡せる
