# 1. デスクトップ UI に Tauri v2 を使う

- 状態: 採用
- 日付: 2026-09-03

## 背景

Meowbox は Rust 製のメーラーで、同期エンジン・SQLite・MCP サーバをすべて 1 つの
プロセスに同居させたい。UI は日本語メールの高密度な一覧とスレッド表示が中心で、
案件タグごとの切り替えやタスク表示など、作り込みの必要な画面が多い。

## 決定

デスクトップシェルに **Tauri v2** を使い、フロントエンドは React 18 + TypeScript で書く。

## 理由

- Rust のコア（`mailcore` / `mailstore` / `mailsync` / `mailmcp`）と同じプロセスに
  同居できる。UI から DB へ行くのに IPC 越しの別プロセスを挟まずに済む
- Windows では WebView2 を使うのでランタイムを同梱せずに済み、配布サイズが小さい
  （Electron のように Chromium を丸ごと抱えない）
- 権限がケイパビリティ単位で明示的。メールという扱いに注意の要るデータに対して、
  「何ができるか」を設定ファイルで説明できる
- フロントを React にしたのは、UI をこのリポジトリの外（Claude Design）で
  作ってから取り込むワークフローを取るため。事例と型定義が最も多い

## 結果

- ビルドに MSVC ツールチェーンと WebView2 ランタイムが要る。CI の Windows ジョブで
  実バンドルを作り、Linux ジョブはコンパイルのみに留める
- モバイルは対象外なので `src-tauri` の crate-type から `staticlib` / `cdylib` を外した
- UI が落ちても CLI と MCP は動く、という設計方針（[[0002]]）は変わらない

## 検討した代替案

- **Electron**: 事例は多いが、Rust のコアを別プロセスにして IPC を挟む必要があり、
  配布サイズも大きい
- **egui / iced（純 Rust GUI）**: 依存は減るが、日本語の複雑なテキストレイアウトと
  デザインからの取り込みやすさで劣る
- **Web アプリ + ローカルサーバ**: ブラウザに寄せると OS の資格情報ストア
  （`keyring`）やファイル保存の扱いが遠くなる
