# 2. 送信ツールを MCP に出さない

- 状態: 採用
- 日付: 2026-09-03

## 背景

Meowbox は MCP サーバを内蔵し、Claude が検索・要約・タスク抽出・返信下書きを
直接行える。ここに「メールを送る」ツールを足せば、Claude が最後まで完結できる。

一方でメール送信は取り消せない。相手の受信箱に届いた時点で終わりで、
誤送信の影響は送信者の信用に直接返ってくる。

## 決定

MCP に公開するツールは **`create_draft` まで**とし、送信ツールを出さない。
実際に送信できるのは UI の「確認して送信」ボタンだけにする。

## 理由

- 取り消せない操作は、人間が内容を見た上で押すべき操作として残す
- MCP のツール一覧そのものが安全境界の説明になる。「送信ツールが無い」ことは
  設定ファイルや README の注意書きより強い保証になる
- 下書きまでを自動化しても、実務上の手間はほとんど減らない。読んで直して送る
  ところが仕事の中身なので、そこを奪わない

## 結果

- `mailmcp` のツール一覧に送信系は入れない（`docs/DESIGN.md` の 6 節）
- UI 側では、Claude が書いた下書きを人間が一度も編集せずに送ろうとしたときに
  確認ダイアログを挟む（`ReplyBox`）。テストで固定してある
- 送信ボタンのラベルは常に「確認して送信」。「送信」にしない
- P4 以降で自動送信の要望が出ても、この ADR を更新してから実装する
