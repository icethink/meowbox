# 4. 人間由来は accent、Claude 由来は ai。2 色を混ぜない

- 状態: 採用
- 日付: 2026-09-03

## 背景

Meowbox の画面には、人間が書いたもの（メール本文、自分の返信、フラグ）と
Claude が書いたもの（要約、抽出タスク、返信下書き、日次まとめ）が同居する。

要約とメール本文が同じ見た目で並ぶと、読み手は「誰がそう言ったのか」を
文脈から推測することになる。要約の誤りをメールの内容だと思い込む事故が起きる。

## 決定

- **人間側**（送信・選択・要対応・フラグ・期限）は `--accent`（橙）
- **Claude 由来**（要約・AI 抽出タスク・AI 下書き・「Claude のまとめ」）は `--ai`（藤）
- この 2 色を 1 つの要素の中で混ぜない

さらに、Claude 由来の情報には次を必ず添える。

- 生成元の明示（「Claude による要約」「Claude のまとめ」）と生成時刻
- 確度の低い抽出タスクは**点線枠**で「候補・確度 62%」と出し、実線の確定タスクと
  枠線の形で区別する

## 理由

- 色と枠線の形は、文言より先に目に入る。読む前に出所が分かる
- 「AI が出した候補」と「人間が受け入れたタスク」を同じチェックボックスで並べると、
  未確認の推測が既定のタスクとして扱われてしまう
- 送信ボタンだけは常に `--accent` にする。押すのは人間だと見た目で示すため
  （[[0002]] の安全境界の一部）

## 結果

- `tokens.css` は `--accent*` と `--ai*` を別系統として持つ。片方を他方の
  ホバー色などに流用しない
- コンポーネントの `tone` プロパティは `accent` / `ai` を排他にする
  （`Badge`、`IconButton`、`Checkbox`）
- ライトテーマを足すときも、この 2 系統の識別しやすさを最優先で調整する
